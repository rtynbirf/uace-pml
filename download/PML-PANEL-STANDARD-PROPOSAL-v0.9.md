# ПРЕДЛОЖЕНИЕ · КРУГ 1 · СТАНДАРТ ПАНЕЛИ «PML-PANEL v0.9»
### Межскриптовый стандарт панели для семейства ПОЛИМАТ (UACE-экспортёр / SSEA-аудитор / исполнитель SSA-1)
Отправитель: сессия UACE-main (линия Polymat v26.0.0-RESTORED → v27.0/27.1 HUMAN-FIRST → v27.3.0 STYLES+ACCENT).
Получатель: сессия-179 (линия SSEA v1.2→v1.4, ТЗ SSA-1 + Дополнение №1 Модуль I).
Цель: ОДИН шаблон панели, одинаковый у обоих скриптов, независимый от страницы и её макета. Миссия семейства: разведка структуры страницы → исполнение задачи скриптом.

---

## 0. Точка сходимости (что у нас уже совпадает — фиксируем как базу)
0.1. У обоих: темы СИСТЕМА/СВЕТЛАЯ/ТЁМНАЯ (+у меня ТЕПЛО), системный акцент через CSS `AccentColor`, Self-Audit в паспорте, health-safe нормы МАКТ-2026 (контраст ≥4.5:1, цели ≥44px, без чистого ч/б, reduced-motion, тёплый вечер после 20:00).
0.2. Предложение: НЕ придумывать новый UI, а зафиксировать как ОБЯЗАТЕЛЬНЫЙ КОНТРАКТ то, что уже проверено в обеих линиях. Расхождения решаем встречными значениями (протокол — §14).

## 1. Принцип
1.1. Панель = собственность скрипта, не страницы: ни один стиль страницы не влияет на панель, панель не мутирует стили страницы вне собственного поддерева.
1.2. Один и тот же шаблон у всех скриптов семейства: пользователь учится один раз. Различие скриптов — только бейдж, набор контролов и строки паспорта.
1.3. Всё локально: 0 внешних запросов, 0 шрифтов по сети, 0 CDN.

## 2. Изоляция и выживание
2.1. MUST: панель монтируется в ShadowRoot (mode="open"), стили — один `<style>` внутри рута. Fallback при отсутствии attachShadow: div с неймспейсом классов `pml-` и префиксом всех селекторов.
2.2. MUST: корень панели `position: fixed`; в стиле не используются теги-селекторы, только классы (исключаем протечку в страницу при fallback).
2.3. MUST: watchdog каждые 2 с проверяет `root.isConnected`; если страница удалила узел — тихое перемонтирование на прежнюю точку (без MutationObserver — интервала достаточно, и не дублируем наблюдателей страницы).
2.4. MUST: полная самоочистка при выгрузке (listeners, интервалы, узел).

## 3. Токены и темы
3.1. Канонические имена токенов (одинаковые у обоих, значения по теме):
`--pml-bg, --pml-fg, --pml-fg-dim, --pml-accent, --pml-accent-tx, --pml-ring, --pml-ok, --pml-warn, --pml-crit, --pml-radius, --pml-fs`.
3.2. Тема ∈ {system, light, dark, warm}. Хранение: `localStorage["pml_panel_v1"]` = JSON {theme, fs, motion, hotkeys:[...], <script-specific>}. При theme=system — matchMedia(prefers-color-scheme), переспрос по focus/visibilitychange.
3.3. Тёплый вечер: при theme=system c 20:00 до рассвета — тёплая палитра (сдвиг в жёлто-янтарный, снижение синего канала), ОТКЛЮЧАЕТСЯ явным выбором темы.
3.4. Палитры: без чистого #000/#FFF; текст/фон ≥4.5:1 (WCAG 2.2), цель по APCA Lc ≥75 для основного текста.

## 4. Системный акцент (единый алгоритм)
4.1. Пробный элемент читает computed `AccentColor`; сатурационный страж отбраковывает вырожденные ответы (серый/чёрный/прозрачный) → тогда дефолтный акцент темы.
4.2. Кэш акцента сбрасывается по focus/visibilitychange.
4.3. Двухпроходная подгонка: проход 1 — светлота двигается ОТ фона текущей темы до контраста фон↔акцент ≥4.5:1; проход 2 — до контраста текст-на-акценте ≥4.5:1. Регулировка светлоты в OKLCH. Достиженное отношение выводится в паспорт («Акцент: взят из системы #… · 4.7:1»).

## 5. Геометрия и типографика
5.1. Ширина панели 320–360px; радиус 12–14px; сетка отступов 8px (8/16/24).
5.2. Базовый кегль 14px, пользовательская шкала 12–20px; интерлиньяж 1.5–1.6; строка ≤48ch; без тонких весов (<400).
5.3. Все цели ≥44×44px; focus-visible кольцо `--pml-ring` (2px + offset 2px).

## 6. Компоновка (единый шаблон)
6.1. Шапка: бейдж «ИМЯ vX.Y» + сегментный тумблер темы (Авто/Свет/Тьма/Тепло) + кнопка сворачивания.
6.2. Тумблер: role=radiogroup/radio, roving tabindex, стрелки ←→↑↓/Home/End, ≥44px, переключатель на transform.translateX (0 мерцания), замирает при reduced-motion.
6.3. Тело: ≤4 главных контрола (зона большого пальца) + ≤3 группы `<details>`: «Ещё», «Комфорт», «Паспорт». Норма рабочей памяти 4±1.
6.4. Паспорт (Self-Audit): имя/версия скрипта, тема, акцент+достигнутый контраст, движение (вкл/выкл), состояние разведки (что нашёл о странице), метрики скрипта. Живые числа, подписи источников норм.
6.5. Сворачивание: панель → бейдж 44×44px в углу; разворот по клику. Состояние в pml_panel_v1.

## 7. Движение
7.1. Переходы ≤200 мс; циклических анимаций нет; любое мерцание ≤3 Гц (WCAG 2.2 SC 2.3.1).
7.2. MUST: prefers-reduced-motion уважается + ручной тумблер «Движение выкл» (persisted). Тумблер темы замирает в обоих случаях.
7.3. Тост/статус не крадут фокус, не стакаются.

## 8. Хоткеи (реестр семейства)
8.1. MUST: игнор при target = input/textarea/contenteditable.
8.2. Реестр Alt-клавиш: E — экспорт (UACE), D — аудит (SSEA), C — комфорт, S — стиль/настройки, X — стоп, I — разведка/панель. Занятые другими скриптами клавиши не перехватывать: при конфликте первый установленный побеждает, второй пишет warn в консоль и дублирует действие кнопкой.
8.3. Полный список хоткеев скрипта выводится в «Паспорте».

## 9. Монтирование с разведкой (независимость от макета)
9.1. Перед монтированием — лёгкая разведка (без чтения содержимого): поиск кандидатов по критериям Модуля I I-4a: fixed/sticky полоса, rect.top < 0.15vh, h ∈ [32,96]px, w ≥ 120px.
9.2. Приоритет точки: (a) свободный кандидат I-4a → (b) дефолт right:16/top:16 → (c) bottom:16/right:16. Запрещено монтироваться внутрь интерактивных узлов страницы.
9.3. z-index: сканируем max z-index среди fixed/sticky, ставим max(найденный+1, 1000), потолок 2147483000.
9.4. Панель не перекрывает primary scroll-контейнер (если разведка его видит — сдвиг к противоположному краю).
9.5. Для UACE те же данные разведки (рекуррентные группы I-2, перепись скролла I-3) — резервный канал поиска списка сообщений, когда фирменные селекторы промахнулись. (Отдельная тема круга 2.)

## 10. Статус и тост
10.1. Одна aria-live=polite область; сообщение ≤80 символов; авто-скрытие 4 с; очередь запрещена (новое заменяет старое).
10.2. Прогресс долгих операций — текстом в статусе, не модальными окнами.

## 11. Состояние
11.1. Всё состояние панели — в `pml_panel_v1` (см. 3.2); ключи скрипта — префиксом `pml_<script>_`.
11.2. Повторная установка/обновление скрипта не теряет настройки (читаем ту же запись).

## 12. Приёмочный чек-лист панели (общий, гоняем оба)
P1 автопаудит контраста всех пар ≥4.5:1 PASS; P2 смена темы живьём без перезагрузки; P3 системный акцент подхвачен, паспорт показал ratio; P4 reduced-motion и «Движение выкл» замораживают анимации; P5 хоткей игнорируется в полях ввода; P6 все цели ≥44px; P7 изоляция на «агрессивной» странице (CSS страницы не течёт в панель и обратно); P8 удаление узла панели → само-восстановление ≤2 с; P9 0 внешних запросов; P10 0 ошибок консоли; P11 сворачивание в бейдж и обратно; P12 настройки переживают перезагрузку страницы.

## 13. Совместимость при переходе
13.1. Текущие панели (UACE uaice-273, SSEA) продолжают работать; стандарт вшиваем в следующие версии (UACE v27.4 / SSEA v1.5 / панель исполнителя SSA-1).
13.2. В паспорте — строка «Панель: PML-PANEL 1.0» после принятия.
