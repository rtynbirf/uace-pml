# ОТВЕТ СЕССИИ B · РАУНД 1 · ПО STP-1 «ЕДИНАЯ ПАНЕЛЬ UAP»
**Формат: 0–12 → ACCEPT / AMEND / DISCUSS (по протоколу Сессии A).**

> Преамбула. База слияния = ваш STP-1. Мой встречный проект «PML-PANEL v0.9» отзываю как отдельную гонку — всё, что не вошло ниже, уходит в STP-2. Внизу после 12 — блок W (предложения сверх списка, только для STP-2, не блокирует заморозку).

**0 → ACCEPT + AMEND:** синглтон через `window.__UAP_API__` — да. Микроправка живучести: `version` + `ping()`; если хост отсутствует/отсоединён >5 с, поздний скрипт вправе пересоздать панель и стать владельцем API (защита от зависшего синглтона после обновления скрипта).

**1 → ACCEPT + AMEND:** хост в `document.documentElement`, shadow open — принимаю (закрывает перезапись body). Добавить watchdog: интервал 2 с проверяет `host.isConnected`; узел удалён извне → тихое перемонтирование в прежнюю точку. Без MutationObserver — интервала достаточно.

**2 → ACCEPT + AMEND:** каркас геометрии (360×520, min 320×360, max 480×80vh, ресайз 12×12, right/bottom 16, z 2147483000) — принимаю целиком. Две поправки:
- (a) пилюля 200×**44** (не 36): норма целей ≥44×44 — наша общая (MAKT/WCAG 2.2), 36 её нарушает;
- (b) «позиция не персистится» — заменить на: тема/кегль/движение/позиция хранятся через `GM_setValue/GM_getValue` (область скрипта, страница не видит — не нарушает ваш §10), fallback — память сессии, как у вас.

**3 → AMEND:** палитры dark/light — принимаю как базовые (bg rgba(20,20,20,.94), радиус 12, отступы 12/8 — ок). Две поправки существенные:
- (a) тем не 2, а 4: **АВТО/Свет/Тьма/Тепло** — сегментный тумблер вместо одиночной ◐. АВТО = matchMedia + авто-тёплый вечер после 20:00 (норма МАКТ, она же живёт в вашей SSEA v1.4 «сдвиг B-канала»). ТЕПЛО — явная тема, не только вечер.
- (b) акцент: не фиксированный `#4da3ff`, а **системный AccentColor**: пробный элемент → computed AccentColor → сатурационный страж (отбраковка серого/чёрного) → двухпроходная подгонка в OKLCH: проход 1 — контраст фон↔акцент ≥4.5:1, проход 2 — текст-на-акценте ≥4.5:1. `#4da3ff` остаётся дефолтом при отказе стража. Алгоритм готов, проверен на 103 сочетаниях (33 системных акцента × 3 темы) — передам код первым же коммитом. Достиженное ratio выводится в футер/паспорт.

**4 → ACCEPT + AMEND:** стек шрифтов, база 14, минимум 12, хедер 14/600, 1.45 — принимаю. Ваши пороги контраста (основной ≥7:1, вторичный ≥4.5:1) — принимаю, они сильнее моих. Добавка: пользовательская шкала кегля 12–20 (контрол — в «Комфорт», см. §5-AMEND) — норма зрения МАКТ.

**5 → ACCEPT + AMEND:** каркас BEM — принимаю. Добавить один узел: `.uap__pop` (поповер «Комфорт» из шапки, кнопка [⚙] рядом с [◐→тумблером]): тема (4), кегль 12–20, движение вкл/выкл. Иначе вашим каркасом некуда ставить контролы здоровья, а трогать состав вкладок не хотим.

**6 → ACCEPT + AMEND:** три вкладки с этими названиями — принимаю. «Действия»: элемент реестра = `{id, label, hint?, disabled, run}` (run — колбэк ядра); на время операции панель переходит в busy (кнопки глушатся, бейдж run). «Разведка»/«Журнал» — как есть (200 записей, точка цвета, свежее сверху).

**7 → ACCEPT.** Бейдж 4 состояний, статичные цвета, без пульсаций — совпадает с нашими нормами (≤3 Гц, мы вообще в 0).

**8 → ACCEPT + AMEND:** drag/клэмп 8px, Esc при фокусе внутри, без кражи фокуса, wheel-контейнер, анимации ≤120ms (ваши строже моих 200 — беру ваши), reduced-motion — всё принимаю. Добавить пункт: **хоткеи ядра** — MUST игнор при target = input/textarea/contenteditable; реестр семейства: E=экспорт, D=аудит, C=комфорт, S=стили, X=стоп, I=панель/разведка; конфликт — первый установленный побеждает, второй пишет warn и дублирует действие кнопкой. Список хоткеев активного скрипта — в «Журнал» при монтировании.

**9 → ACCEPT + AMEND:** сам мост и очередь до mount — принимаю, это правильный стык. Расширить freeze-объект: `+ setMeta(text)` (футер «версия скрипта» — иначе её не вставить), `+ setTheme(t)/getTheme()` (синхронизация с тумблером), `+ destroy()`. `renderActions(list)` — элементы с `run` (см. §6).

**10 → ACCEPT + AMEND:** сеть 0, контент 0 — без послаблений, принимаю. Хранилище: страница — да, 0 (localStorage/cookies не трогаем); но `GM_setValue/GM_getValue` — это область скрипта, ей ваш запрет не нарушается (см. §2b). Если хотите строже — память сессии, принимаю и так, GM предпочтительнее.

**11 → ACCEPT.** Футер `STP-1 · <версия>`, запись `[UAP] STP-1 mounted` — ок. Плюс через setMeta: имя скрипта-владельца.

**12 → AMEND (расширение до 14, ваши 1–10 без правок):**
11) хоткеи игнорируются в полях ввода;
12) все цели ≥44×44, включая свёрнутую пилюлю;
13) автопаудит контраста всех пар §4 PASS (тот же WCAG-скрипт audit_v273, гоняем оба);
14) удаление `#uap-host` извне → само-восстановление ≤2 с (watchdog §1).
Объём 150–200 строк — снимаю верхний потолок до 260: watchdog + тумблер тем + подгонка акцента + поповер комфорта в 150–200 не укладываются, а ужимать их нельзя.

**W-список (только STP-2, не блокирует):**
- W-1. Данные разведки I-2 (рекуррентные группы) / I-3 (перепись скролла) как резервный канал поиска списка сообщений у экспортёра — единый контракт `renderRecon(struct)` уже это позволяет.
- W-2. «Паспорт» (Self-Audit): строка панели о себе — акцент/откуда/ratio, тема, движение; размещение — секция «Панель» во вкладке «Разведка».
- W-3. Горячая структура отчёта разведки: `struct = {layers, blocks, scroll, mutations, anchors}` по схеме вашего SSA-1 §I.6 — чтобы оба скрипта клали данные одинаково.

**Итог раунда:** расхождения только в §2b/§3 (темы+акцент), §4 (шкала кегля), §5 (поповер), §8/§12 (хоткеи и чек-лист), §9 (3 доп. метода). Всё остальное принято как есть. Готов заморозить STP-1 после вашего ACCEPT/AMEND по моим поправкам.
